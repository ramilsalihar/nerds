# Color System

Source: the edtech dashboard reference (indigo sidebar, pastel course tiles, warm avatar chips, amber ratings). Implemented in [frontend/src/styles/tokens.css](../frontend/src/styles/tokens.css).

## Structure

Three layers, same shape as the existing label/background/fill hierarchy so light/dark keeps working the same way:

1. **Brand** — the app's one fixed identity color. Not theme-dependent.
2. **Accent set** — 9 hues used for avatar chips, cover tiles, status pills, charts. Each hue ships in up to three tones.
3. **Neutrals** — the label/background/fill/separator roles, now lavender-tinted instead of iOS gray.

## Brand

| Token | Value | Use |
|---|---|---|
| `--brand-primary` | `#4640DE` | Sidebar, active nav, primary buttons, links, focus rings — the one color that means "interactive/brand" |
| `--brand-primary-dark` | `#2F2B9C` | Hover/pressed state, gradient end for promo/hero cards |

Renamed from `--brand-navy` → `--brand-primary` (the old value, `#16233F`, was closer to navy; the new one is the vivid indigo from the reference). Every component that meant "the brand color" (`Button`, `TextField` focus ring, nav links) was repointed from the old `--color-blue` to `--brand-primary` — before this pass, "primary action" and "one of nine decorative accents" were the same variable, which stopped being true once a real 9-hue accent set existed.

## Accent set — three tones per hue

| Hue | Vivid (fills, tints, dots, large decorative text) | Strong (text, or white/light text on a solid fill) | On-dark (badges on `--brand-primary-dark` surfaces) |
|---|---|---|---|
| blue | `#4FA8E0` | `#207CB7` | — |
| green | `#2ECC9B` | `#1E8666` | — |
| indigo | `#4640DE` | `#4640DE` (already compliant) | — |
| orange | `#F2994A` | `#B85E0D` | — |
| pink | `#FF6F91` | `#ED0038` | `#FFB8C8` |
| purple | `#9B8AFB` | `#745CF9` | — |
| red | `#FF5C5C` | `#EE0000` | — |
| teal | `#2FBFA8` | `#218475` | — |
| yellow | `#FFC93C` | `#9A6F00` | — |

**Why three tones:** the reference palette is deliberately light and pastel-leaning. Every vivid tone in that table sits below WCAG AA (4.5:1) as white text or as text-on-white — measured, not eyeballed (e.g. white on vivid teal is 2.30:1). Vivid tones stay great for what they're for — backgrounds, tints, dots, chart segments, or genuinely large bold text (≥3:1 is the bar there). The moment a hue *becomes text*, or *sits under white/light text as a solid fill*, swap to `-strong`. `-strong` was generated by darkening each vivid hue (same hue/saturation, less lightness) until it cleared 4.5:1 against white — so it's the same family, just legible.

`-on-dark` is a third case: pink used to label a chip that sits on the dark `--brand-primary → --brand-primary-dark` promo card. `-strong` is *darker*, which makes contrast *worse* against a dark background — so on-dark badges need a *lightened* variant instead. Only added for pink so far, because that's the only current on-dark badge; add more hues here only when a real usage needs one, computed the same way (lighten until ≥4.5:1 against the dark surface it sits on).

## Usage rule

- Hue **is** the text (link, status label, error message, pill label, money amount) → `-strong`
- White/light text **sits on** the hue as a solid fill (avatar initials, cover-tile letter, switch track, filled button on a colored bg) → `-strong`
- Hue is a **background tint, border, dot, or chart fill** with no text directly on the saturated color → vivid (default)
- Badge/text on the dark brand gradient specifically → `-on-dark` (add the hue if it doesn't exist yet, following the derivation above)
- "The" interactive color (buttons, focus rings, primary links, active nav) → `--brand-primary`, not any accent hue

`frontend/src/lib/color.ts` has two helpers built on the same deterministic per-id hue pick:
- `colorFor(id)` — solid `-strong` fill for avatar chips (matches the reference's solid photo-circle avatars)
- `tileFor(id)` — `{ background, color }` pair for cover tiles: an 18% tint of the hue's `-strong` tone behind, the `-strong` tone itself as the letter color (matches the reference's pastel course-card tiles). The 18% tint was chosen because it's the highest tint that still clears 3.5–4.5:1 for every hue at large-bold text size — enough margin to stay legible while staying visibly pastel.

Callers never pick a tone by hand — both helpers bake the accessible pairing in.

## Neutrals

Backgrounds and fills shifted from iOS neutral gray to a lavender tint to match the reference's cool off-white canvas:

| Token | Light | Dark |
|---|---|---|
| `--bg-grouped-primary` (page canvas) | `#EEF0FA` | `#0F1024` |
| `--bg-grouped-secondary` (cards) | `#FFFFFF` | `#181A37` |
| `--fill-quaternary` (subtle control bg) | `rgba(98, 91, 158, 0.06)` | `rgba(150, 145, 220, 0.1)` |
| `--label-primary` | `rgba(20, 20, 43, 0.88)` | `rgba(255, 255, 255, 0.88)` |

Label and separator contrast against the new backgrounds was checked too — `--label-primary` on `--bg-grouped-primary` is 15.9:1, far above AA.

## What changed in the codebase

- `frontend/src/styles/tokens.css` — full palette rewrite (accent set, brand rename, neutral retint, light/dark/`[data-theme]` blocks)
- `frontend/src/lib/color.ts` — `colorFor()` now returns the `-strong` tier; added `tileFor()` for pastel-tile-plus-colored-letter cover tiles
- `ProjectCard` cover tiles switched from a solid `-strong` fill with a white letter to `tileFor()`'s pastel-tint-plus-colored-letter treatment — this is the one place the earlier pass still didn't visually match the reference (it had the right hues but the wrong tone pairing: solid saturated tiles instead of the reference's soft pastel ones)
- Every component/page that referenced `--color-blue` for "the brand color" now uses `--brand-primary`: `Button`, `TextField`, `Topbar`, `Dashboard` (see-all link), `AuthForm` (switch link)
- Every component/page that uses a hue as literal text now uses `-strong`: `PillFilter`, `ProjectForm`, `Switch`, `Dashboard` (inflow amount, promo button), `Admin`, `Donate`, `AuthForm` (error), `Dashboard.tsx` (inline error)
- `Dashboard.css` promo tag uses the new `-on-dark` pink

No component structure changed — this was a token-and-reference pass, not a redesign.
